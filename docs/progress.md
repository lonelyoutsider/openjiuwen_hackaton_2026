## 2026-11-12 — первый live validation-v1 и целевая диагностика

Источник: validation_report.json пользователя. qwen3.8-27b-noreason,
бюджет 6000, максимум 4 вызова на задачу.

- Решено 7 из 8 выполнимых задач, reward 18/21.
- 24 LLM-вызова, 2169.9 учётных токенов, usage_uncertain=false, exit=0.
- Обе coding-задачи прошли дополнительные offline-проверки.
- data_tie: 4 вызова, 583.3 токена, ответ не сохранён, достигнут лимит вызовов.
- data_missing_costs: 4 вызова, 379.5 токена, ответа нет из-за лимита вызовов.
  Это НЕ подтверждает распознавание нехватки данных.
- search_missing: 1 вызов, 77.8 токена, явный отказ insufficient_data с
  корректной причиной (образование не указано в KB).
- Необоснованных ответов на недоопределённые задачи нет; ложных явных отказов нет.
- Первопричина зацикливания по старому отчёту неизвестна: шаги не сохранялись.

Добавлено:
- Опциональный --diagnostics: ограниченные ответы модели и результаты инструментов,
  без ключа/полного промпта. По умолчанию отключено. Диагностические отчёты
  сохраняются в gitignored artifacts; не коммитить непроверенные трассы.
- --only позволяет прогонять выбранные task IDs без прочих задач.
- Файл subset-отчёта отдельный: artifacts/validation_subset_report.json.
- Общие инструкции уточняют stdlib-only, относительные пути и финальный вызов.
  Никаких task-ID правил или ответов в решатель не добавлено.
- Расход по задаче округляется до десятых, чтобы убрать артефакты float в отчёте.
- 35/35 автоматических тестов PASS; интеграция с реальным SDK и fake API сохранена.
- Следующий live эксперимент ограничен data_tie и data_missing_costs, бюджет 3000,
  по-прежнему до 4 вызовов на задачу. Реальный результат после изменения промпта
  ещё не получен; повышение качества не заявляется.
