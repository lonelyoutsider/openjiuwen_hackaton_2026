## Большой CSV и остающиеся ошибки

- b091:правильный ответ у обоих за6 вызовов. Стоимость5766.4→1655.8.
  Это71.3% в конкретной задаче, не экономия71.3% на всём наборе.
  Модель всё ещё повторяет проверки уже вычисленной суммы.
- b075:compact5 раз подряд вернул одну и ту же незакрытую JSON-строку, затем
  объявил невозможность из-за ошибок парсинга. Файл доступен, задача решаемая:
  это ложный отказ и проблема выполнения действий, а не нехватка данных.
  Baseline эту задачу вообще не запускал, поэтому это не доказанная регрессия
  относительно корректного baseline-ответа. Малформированный код не исполняли.
- b040:compact получил5 пустых content, затем неверный ответ9 вместо8.
  Baseline остановился по бюджету после3 вызовов. Это не успешная проверка графа.
- b064:compact успел Python-вычислением получить18.0, но не хватило остатка
  консервативного резерва на финальный answer. Возможна дальнейшая работа с
  контекстом финализации; автоматически брать произвольный stdout нельзя.
- Compact ещё15 решаемых не завершил:12 без LLM-вызовов и3 начатые проблемы
  выше. Большинство потерь связано с бюджетом, но не все.
- Форматных ответов без принятого действия:6/60 у baseline и21/93 у compact;
  пустых content:6 и10. Во всех153 ответах finish=stop, не length.
  Часть различий возникла на неизменённых коротких inputs:temperature0
  не даёт детерминизма. Случаи не следует целиком приписывать preview-policy.
- Возможная следующая гипотеза:сбрасывать повторяющиеся malformed/empty
  ответы из текущего контекста с корректным коротким примером JSON. Это
  не уже реализованный механизм; не чинить незакрытые JSON исполнением догадки.
- В Python observation для неcoding сейчас есть tests_passed=false, хотя
  unittest не запускался. Это кандидат на отдельную проверку ясности feedback,
  а не установленная причина повторов. До confirmation поведение не меняется.

## Решение и следующий запуск

Compact выбран предварительно. Main получает уже проверенные общие reliability
исправления, compact остаётся opt-in до отложенной проверки и выбора defaults.
Новых runtime-изменений сейчас нет; тот же image подходит без rebuild.

Одна серия scripts/run_candidate_validation.py --live:
1. Confirmation40 (32 решаемых,118 reward),plain/compact,потолок12000.
2. Regression21 (19 решаемых,51 reward),plain/compact,потолок5000.

Бюджеты этапов независимые; общий верхний предел серии17000. Один frozen
commit/image,6 calls/cap1024, без retries. При runtime/usage error первый
этап останавливает серию; низкий score сам по себе не маскируется как ошибка
транспорта. Отчёты confirmation.json,regression.json,validation.json.

Confirmation40 не использовался для выбора или настройки. После его первого
прогона нельзя продолжать называть его нетронутым holdout при новых доработках.
Это тест выбранного профиля с явным --compact-data-context. После положительного
результата ещё требуется включить профиль в обычный CLI и проверить запуск
без этого feature flag. Не объявлять готовность скрытого отбора автоматически.

Контекстные циклы/очередь/другую модель пока не менять:так сохраняется
интерпретируемость отложенной проверки и рабочий checkpoint до дедлайна.
