# E01 — наличие точечного edit-инструмента

Статус: первая live-пара завершена; оба варианта reward4/9.
Подробности: [e01-result.md](e01-result.md). Следующий запуск —
[E01b action-format](action-format.md); исходную пару вслепую не повторять.

## Гипотеза

Точная замена короткого блока может снизить выходные токены и ошибки
генерации coding-правок при сохранении корректности. Основание: исследование
Pi/Aider, docs/harness-research-2026-11-12.md. Измеренного выигрыша пока нет.

## Контроль и вариант

- Оба варианта используют один снимок кода, один Docker image ID и одну модель
  qwen3.8-27b-noreason; задания каждый раз создаются в чистом каталоге.
- Baseline: текущие read/python/write/answer/abstain, edit отключён.
- Edit: те же инструменты и дополнительное действие edit; write остаётся доступен.
- Python-код baseline тоже может изменять исходники в разрешённом workspace.
  Не запрещать этот путь: исследуем пользу нового инструмента в реальном агенте.
- Добавленное описание edit входит в измеренную стоимость промпта варианта.
- Максимум 4 вызова на задачу, max_output_tokens1024, до 300 секунд на вариант.
- По 3000 учётных токенов на вариант: потолок одной пары 6000; без автоповторов.
- Резервирование консервативное: вариант может остановиться раньше исчерпания
  фактического бюджета, если следующий запрос не помещается с запасом.

## Набор

scripts/coding_edit_set.py создаёт три авторских случая, available_reward=9:

| Случай | Что проверяет |
|---|---|
| coding_ledger | Точечная правка в более длинном модуле; Decimal, возвраты, неизвестные категории, генераторы; сохранность соседних функций |
| coding_intervals | Замкнутые интервалы, общие границы, вложенность и неизменность входа |
| coding_tags | Два связанных файла, порядок, пустые значения, Unicode casefold и whitespace |

Это небольшой диагностический набор для разработки, не репрезентативный
benchmark. После использования для выбора он перестаёт быть новым holdout.
Родственные будущие варианты держать в соответствующей validation-группе.
expected удаляется до запуска; private_check и validation_group остаются только
у offline-оценщика. Частичное исправление, проходящее видимые тесты, может
провалить независимую проверку. Модель эту проверку не получает.

## Запуск на Windows

Из корня экспериментальной ветки с чистым git status:

```powershell
docker build --progress=plain -t its-ia:edit-experiment .
py scripts/run_edit_experiment.py
py scripts/run_edit_experiment.py --live
```

Вторая команда проверяет параметры и не обращается к API. Третья выполняет
одну пару; ключ берётся из локальной переменной LLM_API_KEY либо вводится
скрыто. Не вставлять ключ в чат или командную строку. Docker Desktop должен
работать. Локальная установка openJiuwen для этого скрипта не нужна.

Скрипт проверяет чистоту tracked-файлов и копирует только git-tracked файлы
во временный снимок. Непроиндексированный .env туда не входит. Снимок кода
монтируется read-only; копии задач создаются в /tmp. Секрет передаётся Docker
через окружение, не через аргумент с его значением. Пара выполняется последовательно.
При ошибке первого варианта либо usage_uncertain второй не запускается.
Возможен --order edit-first, но повтор пары оплачивается отдельно и не автоматизирован.

## Результаты

В artifacts/edit-experiment-<UTC>-<id>/ сохраняются:

- baseline.json и edit.json: результаты, input/output, weighted tokens,
  ограниченная диагностика и полученные coding-исходники;
- comparison.json: commit, image ID, порядок, конфигурация, сводки и общий расход.

При незавершённой паре weighted_tokens=null, reported_weighted_tokens —
только доступная часть расхода; это не доказательство нулевой стоимости
недостающего запуска.

Артефакты gitignored. Не коммитить сырые отчёты; сначала изучить локально.
Для разбора в этом чате передать comparison.json и оба отчёта вариантов.
Если пара остановилась, сначала разобрать причину; не запускать её повторно
вслепую. Смена image tag сама по себе не гарантирует новую сборку.

Сначала сравниваем суммарный reward, затем стоимость при одинаковом reward,
дополнительно — output/input, число действий, ошибки и время. Один прогон
не доказывает преимущество. Время включает старт Python/SDK и зависит от среды.
При принятии изменения нужны регрессия на остальных типах и проверка контейнера.

## Границы инструмента

edit работает только при --enable-edit и только для coding. Разрешены
существующие non-test .py, уникальный непустой old_text и изменяющий new_text.
Синтаксис проверяется до атомарной замены. Неверные или неоднозначные правки
не изменяют файл. Неуспешный по тестам кандидат остаётся в приватной копии;
оригинальные исходники публикуются только после успешных тестов.
Контейнер остаётся границей изоляции; этот инструмент не заменяет sandbox.
