# E01c — совместимость JSON-режима и смешанная проверка

Статус13 ноября: probe успешно выполнен пользователем — prompt27/output10,
reasoning0, корректный answer/OK,12.7 учётного токена. Повторять probe не нужно.
Немедленный шаг — одна смешанная A/B-пара; см. ../final-day.md.

Основание: E01b подтвердил пользу принятия полного JSON после пояснения,
но часть ответов содержала только обещание сделать действие. Разборщик
не может восстановить несуществующую команду.

## Первичный источник

[NeuralDeep structured output](https://neuraldeep.ru/docs/structured.md),
проверено12 ноября2026: документирован response_format с type=json_object
и json_schema. Пример использует gpt-oss-120b. Наличие описанного API не
доказывает поддержку этого параметра каждой конкурсной Qwen и финальным
прокси соревнования. Используем только разрешённую Qwen; чужую модель не вызываем.

## Первоначальный probe — уже выполнен

В текущей экспериментальной ветке:

```powershell
git pull --ff-only
py scripts/smoke_api.py --json-mode
```

Локальная установка SDK и новая сборка Docker для probe не нужны. Один запрос
к qwen3.8-27b-noreason, max_tokens32, маленький фиксированный prompt, без
автоматического повторения или fallback без параметра. Ключ вводится скрыто.
Сохранять его в git/чате не требуется. Фактический расход выводится из usage.

Проверяем HTTP-успех, точное JSON-действие answer/OK и наличие корректного usage.
JSON-shaped ответ не доказывает, что сервер применил грамматику: он мог
выполнить prompt и без неё. Это только первоначальная проверка совместимости.
Если ответ неверен, usage отсутствует или HTTP-запрос отклонён, остановиться
и разобрать результат. Автоматически повторять на другой модели нельзя.

## Подготовленная следующая пара — после анализа probe

JSON-режим выключен по умолчанию. В паре text/json одинаковы edit/recovery,
модель, prompt, лимит4 вызова/задачу, output cap1024 и резерв. Меняется
response_format; размер его сериализации учитывается при резервировании.
Реальный usage по-прежнему prompt/10 + completion, reasoning повторно не добавляется.
JSON-объект не гарантирует правильного action или правильного Python-кода:
все проверки остаются необходимыми.

Следующая диагностическая площадка — весь validation-v1: четыре типа,
8 решаемых и2 с недостающими данными. Это уже использованный набор, поэтому
сравнение служит регрессией; затем нужны свежие группы/случаи.
По4000 на вариант, максимум8000 на одну пару, без автоматических повторов:

```powershell
docker build --progress=plain -t its-ia:edit-experiment .
py scripts/run_edit_experiment.py --comparison json-mode --suite validation --budget-per-arm 4000 --live
```

Probe разобран13 ноября: следующая одна пара допускается по этому плану.
Автоматического повторения серии нет. Артефакты пары:
artifacts/json-mode-experiment-*/comparison.json, text.json, json.json.

До финального включения требуется проверить совместимость финального прокси.
При отсутствии поддержки остаётся режим без нового API-параметра с recovery.
Не разрешать runtime-сеть за пределами конкурсного прокси.
