# E01b — приём полного JSON после пояснения

Статус: live-пара завершена, strict3/9 и recover5/9.
Результат: [e01b-result.md](e01b-result.md). Следующий шаг —
[небольшой JSON-mode probe](json-mode.md), не повтор этой пары.

Основание — E01: модель вернула правильный edit для интервалов, но пояснение
перед ним привело к JSONDecodeError. На edit-варианте 4 из 6 ответов не прошли
разбор; инструмент edit не исполнился ни разу. См. e01-result.md.

## Два варианта

| Вариант | Edit | Recovery |
|---|---|---|
| strict | включён | выключен |
| recover | включён | включён |

Одинаковы модель qwen3.8-27b-noreason, исходные задачи coding-edit-v1,
4 вызова/задачу, выход1024, по 3000 учётных токенов; максимум 6000 на пару.
Один снимок коммита и image ID, чистые копии задач; prompt, история и бюджетный
резерв одинаковы. Меняется только разбор ответа модели. Варианты уже использовались
для диагностики; это не новый holdout. Общий score скрытого набора не прогнозируем.

## Правила recovery

- Принимать строгий JSON и прежнюю целиком ограждённую JSON-команду.
- Опционально принять один полный терминальный JSON-объект после пояснения,
  если он в точности соответствует одной объявленной схеме действия.
- Не выбирать один объект из нескольких и не восстанавливать оборванный JSON.
- Не игнорировать лишние скобки, повторённые ключи, лишние поля или текст
  после команды. Пояснение не исполняется. Правила путей, тестов и tools неизменны.
- Если ответ содержит только пояснение, это по-прежнему ошибка формата.
- API-вызова для исправления формата нет. Дополнительных повторов не добавлено.
- Сохранять исходный ответ в истории: эффект сокращения контекста отдельно не тестируется.

## Диагностика

В --diagnostics у успешных ответов появляются finish_reason, reasoning_tokens
(null, если провайдер не сообщил), input/output и размер текста. Reasoning
не добавляется к completion второй раз. У локальной остановки сохраняются
request_sent=false, оставшийся бюджет и требуемый резерв.
Секреты, headers и полный запрос в эту метадату не входят.

Без диагностического флага новые метаданные в отчёт не сохраняются.
Новые response_format/tools параметры API не используются: контракт провайдера
не расширяется. Это эксперимент разборщика, не принудительная JSON-генерация.

## Локальный запуск

В той же ветке experiment/coding-edit-ab после получения обновления:

```powershell
git pull --ff-only
docker build --progress=plain -t its-ia:edit-experiment .
py scripts/run_edit_experiment.py --comparison action-format
py scripts/run_edit_experiment.py --comparison action-format --live
```

Dry-run не вызывает API. Live выполняет одну последовательную пару и
сохраняет strict.json, recover.json, comparison.json в отдельный каталог
artifacts/action-format-experiment-*. Ключ вводить скрыто локально.
Старую E01-команду без --comparison action-format сейчас не повторять.
При ошибке либо неопределённом usage второй вариант не запускается.

Проверить reward, расход, реально исполненные действия и action_parse,
а не только отсутствие исключений. Лимит бюджета может по-прежнему мешать
завершению ledger; adaptive output cap не входит в эту пару.
Независимые coding-проверки остаются у offline-оценщика.
