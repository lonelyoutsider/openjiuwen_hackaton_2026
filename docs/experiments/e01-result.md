| coding_intervals | 0 вызовов; недостаточно резерва | 1 вызов, 370.3; пояснение + верный JSON edit отвергнуты парсером, затем отказ резерва |

Задачи фактически шли по reward: tags → ledger → intervals. Строки отчёта
выведены по имени, поэтому их порядок не является порядком исполнения.

1. coding_tags прошёл и видимые, и независимые offline-проверки. Baseline сначала
   прислал лишнюю фигурную скобку, затем использовал несуществующий
   unicodedata.casefold и исправился по ошибке. В edit-варианте два ответа
   содержали пояснение вне JSON; реальные изменения выполнялись через write.
2. coding_intervals в edit-варианте содержал полную корректную команду, которая
   меняла сравнение границы и сохраняла максимум правой границы. Строгий
   json.loads отверг ответ из-за текста перед объектом. При локальном
   воспроизведении именно этого действия на исходном кейсе прошли видимые
   и независимые проверки. Это бесплатная проверка записанного действия,
   не новый Qwen-прогон и не новый live score.
3. Оба coding_ledger-ответа не содержали исполнимого JSON. Нельзя выдумывать
   действие из пояснения. Baseline usage достиг 1024 output, но finish_reason
   и reasoning_tokens не сохранялись: причину соотношения usage и видимого
   текста задним числом установить нельзя.

## Почему budget_stop до 3000

Перед запросом резервируется UTF-8-размер JSON-пакета + запас оформления +
полный разрешённый выход. Это консервативная оценка, не фактический usage.
Остатки в конце вариантов: 1088.4 и 1294.7. Их недостаточно на полный выход1024
вместе с резервом входа. Это локальная остановка до отправки запроса, не отказ
API, не обязательно фактическое исчерпание 3000 и не невыполнимость задачи.

Улучшение резерва/адаптивный cap остаётся отдельной гипотезой. В следующей паре
правила резервирования и бюджет не меняются, чтобы проверить один фактор.

## Следующее решение

Сначала E01b: strict vs recovery полного терминального JSON-действия.
В обоих вариантах edit включён, модель/задачи/бюджет одинаковы; меняется только
доступность ограниченного восстановления формата. Prompt и история не переписываются.
Добавляется диагностика finish_reason, reasoning usage и резерва запроса,
но API-параметры и стоимость учёта не изменяются.
Протокол: [action-format.md](action-format.md).

До нового измерения ни edit, ни recovery не включаются по умолчанию.
