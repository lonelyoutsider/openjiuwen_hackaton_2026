## Причина остановки

Последний workflow b091 завершил вычисления/запись ответа, после чего SDK выдал
[100101] workflow execution exceeded time limit of60 seconds.
Это внутренний лимит openJiuwen0.1.19 на один workflow, не общий час и не
исчерпание15000. Неперехваченное исключение завершило обработку всей очереди.

Установленный requirements.lock SDK проверен по исходникам:
- core/session/config/base.py задаёт WORKFLOW_EXECUTE_TIMEOUT=60;
- core/workflow/workflow.py применяет этот таймаут вокруг invoke;
- Runner.run_workflow(...,envs=...) имеет параметр, но текущая реализация
  не передаёт его в подготовку сессии. Просто добавить envs в Runner недостаточно;
- публичная create_workflow_session(envs=...) действительно передаёт override.

Исправление: явная сессия с timeout=остаток общего deadline+30с на публикацию
и cleanup. Глобальный deadline3300с, лимиты HTTP/инструментов и общий BUDGET
сохранены; новый лимит не разрешает бесконечный запуск. Таймер SDK теперь
не прерывает допустимую длинную задачу раньше собственного времени агента.

Учёт: run_usage выводится в finally даже при ошибке. Оценщик использует
авторитетный общий ledger, показывает unassigned cost, а при отсутствии ledger
после LLM-запуска помечает usage неполным. По старому отчёту все49 ответов и
их usage записаны; новый механизм устраняет зависимость учёта от наличия
успешно записанного task record у последней задачи.

Дополнительно исправлен найденный кодовым аудитом crash: SyntaxError при write
исходника возвращается модели как ошибка инструмента для исправления, а не
обрывает весь процесс. В E03 coding не запускался; эта ошибка там не наблюдалась.

## Где расходуется бюджет

b091, большой CSV:5981.4 токена —56.5% всего записанного расхода.
Уже первый Python-вызов прочитал все1800 строк и получил правильное1877.
Затем модель ещё четыре раза проверяла файл, строки и сумму, прежде чем
в шестом вызове записала ответ. Вход вырос с8370 до9729 токенов на запрос.
Это реальная неэффективность, но причинность связи с большим preview пока
не доказана. Нельзя утверждать, что один новый prompt уже устранил повторения.
Оба long-tail search были решены за2 вызова примерно по480 токенов.
