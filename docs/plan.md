# Рабочий план

План команды, не дополнительные требования организаторов.

## Архитектура

1. Загрузить разрешённые поля всех задач, проиндексировать доступные файлы.
2. Решить безопасно распознаваемые задачи детерминированно без LLM.
3. Для остальных оценить вероятность успеха, цену и риск нехватки данных.
4. Выбирать по ожидаемой выгоде: reward * P(correct) / predicted_weighted_tokens.
   Это эвристика; при наличии данных сравнить с бюджетным knapsack-планированием.
5. Запускать ограниченный coding/tool агент, выбирать модель и max output,
   обновлять бюджет после каждого вызова, проверять ответ локальными средствами.
6. После каждого решения атомарно сохранять answer.txt, продолжать при сбоях
   отдельной задачи. Не оставлять выдуманный ответ на невыполнимые задачи.

## Валидация

Основной результат — reward при фиксированном бюджете и времени.
Дополнительно: solved, weighted_tokens, reward/1000 tokens, ошибки по типам,
ложные пропуски, время. MAE оценщика — диагностика, не главный score.
Все варианты одной основы держать в одной группе train/validation.
Будущие шаги и expected не давать планировщику/агенту.
Сравнить: без планировщика → reward-first → reward/cost → reward*P(success)/cost.
Публичные 8 примеров — smoke test, по ним нельзя оценить обобщение.
До массовых API-запусков установить явный лимит эксперимента.
